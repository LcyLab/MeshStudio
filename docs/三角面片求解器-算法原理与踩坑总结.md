# 三角面片求解器：算法原理与踩坑总结

> 整理来源：Codex 会话记录（2026-09-11 ~ 2026-10-05，共 147 个 rollout）、项目内文档
> （`ARCHITECTURE.md` / `CONTEXT.md` / `findings.md` / `progress.md` / `task_plan.md` /
> `docs/superpowers/plans/*` / `docs/references/README-shewchuk-failure-analysis.md`）与源码本身。
>
> 目的：回答两个问题 —— **这套算法到底是怎么工作的**、**开发过程中到底踩了哪些坑**。
> 因为算法是 AI 从论文和开源源码对照着写出来的，这些坑大多不是"手滑写错"，而是**路线选择、
> 数值判据、几何建模**三个层面的系统性偏差，值得单独记档。

## 0. 先说结论（TL;DR）

1. **主体**是 MeshStudio 里的**自研 CAD 表面三角网格引擎**（代码里叫「三角面片」，
   入口 `mesher::generateCadSurfaceMesh`）。技术路线是
   **参数域受约束 Delaunay 三角化（CDT）+ 三维判据自适应细化**，一共 8 个步骤。
2. **不是调库**。Gmsh 只在测试里当对照物（外部审计、固定 T3 输入），生产链路是纯 C++ 自研
   （`src/core/mesher/`，约 12100 行）。上游的 STEP/IGES/BRep 离散仍然用 OCC。
3. **踩的坑分五层**，按"代价 × 隐蔽性"排序：
   **路线/理论** ＞ **数值谓词** ＞ **几何拓扑建模** ＞ **性能复杂度** ＞ **工程流程**。
4. 最贵的一个坑不是 bug，而是**路线选择**：四面体核心走了 Shewchuk 论文里明确警告的
   *almost Delaunay* 路线，导致"细化不可保证正确、容易产生极短边、可能无限细分"——
   文档里已经定性为**理论宿命**，不是实现缺陷。
5. 最赚钱的一个坑是**性能**：`move.stp` 的核心耗时从 **99.82 s → 2.83 s（约 35×）**，
   几乎全部来自两件事——「别在热循环里做 O(T) 全网格校验」和「别每次几何查询都重建 OCC 适配对象」。
6. 当前状态：凹球（`concavaball`）已达标（0 残差、严格 √2）；`phone` 仍有 4291 条软质量残差，
   最差面 818 的 238.5 未解决。**没有导出**（只有截图），**没有用户手动 GUI 验收**。

## 1. 这套东西是什么

### 1.1 定位

**薄 UI + 厚引擎**。Qt 界面只负责收参数、调引擎、展示结果；算法逻辑全部在
`mesher` 纯 C++ 库里（不依赖 OCC / Qt / VTK），由 `SurfaceMeshEngine` / `TetMeshEngine`
做适配层，`OccCadGeometry` 做 OCC 几何查询适配。

分层边界（`ARCHITECTURE.md`「调用边界」）：

```
MainWindow (Qt)
   └─ SurfaceMeshEngine ── OccCadGeometry (OCC 适配) ──┐
                                                        ▼
                              mesher::generateCadSurfaceMesh  ← 纯 C++ 核心
   └─ TetMeshEngine ──── ShapeTessellator (OCC 离散) ──┘
```

### 1.2 数据流：两条输入路径

```
STL ──(vtkSTLReader)──────────────────────────────────────────┐
                                                              ▼
STEP/IGES/BRep ─ ShapeLoader ─ TopoDS_Shape ─┬─► ShapeTessellator ─► weldSurfaceMesh ─► 三角形汤 ─► TetMeshEngine
                                             │   (逐面 BRepMesh_IncrementalMesh)  (3×3×3 邻域容差焊接)
                                             │
                                             └─► OccCadGeometry ─► generateCadSurfaceMesh
                                                                  (自研：参数域 CDT + 细化)
```

**关键认知**：STL 本身就是三角汤，可以直接喂；而 **STEP / IGES / BRep 是边界表示
（B-Rep），面由 NURBS/解析曲面定义、棱由曲线定义，本身完全不含三角面片**。所以
"三角面片从哪来"这个问题，对后一类格式是**必须自己造**，不是可选项。

自研表面引擎**不走** `ShapeTessellator`，而是直接从 OCC 查曲线 / 曲面 / 一阶导数 / 法向 /
参数范围，在参数域里自己剖分——这样才能控制共享棱、面标签和逐角 UV。

## 2. 算法原理

### 2.1 为什么选这条路线

选型是在 2026-09-30 定下来的。当时对比过的候选：

| 候选 | 结论 | 理由 |
|---|---|---|
| **参数域 CDT + 自适应细化（选定）** | ✅ | 能保留 CAD 拓扑、共享棱、面标签；可复用二维网格基础；可给四面体复用 API |
| 直接调 Gmsh | ✗ | 无法控制共享棱/标签一致性，也无法形成自研算法能力 |
| Frontal-Delaunay（Gmsh 算法 6） | 参考 | 用局部度量 + 活动边候选；作为后续对照方向，首版不切换 |
| TetWild / ε-近似 | ✗ | 表面是近似，不适合 FEM 精确边界 |
| 纯 marching / 曲面参数化重网格 | 后置 | 路线完全不同，首版不引入 |

论文依据（分基础与近期两档，文档里明确区分"读过"的程度）：

- **基础**：Ruppert 1995、Shewchuk 的二维细化说明、CGAL `Mesh_2` 文档。
  注意：**平面 PSLG 的角度/半径边比终止条件不能直接搬到变度量 CAD 曲面上**。
- **近期**：2024《精度可控的边界表示模型网格生成》（共享边成对编辑要考虑相邻曲面误差）；
  2024《Alternating size field optimizing and parameterization domain CAD model remeshing》
  （全文 403，只读了摘要与方法片段）；2025-12 在线 / 2026-01 刊《Robust tessellation of
  CAD models without self-intersections》（**CDT 本身不保证映射后三维无交**）；
  2026-04 预印本《Topology-First B-Rep Meshing》（把 B-Rep 拓扑当不变量）。
- **开源对照**：Gmsh 4.15.2 源码包（`buildMetric` / `bowyerWatson` / `optimalPointFrontal` /
  `meshGFaceBDS`）、CGAL v6.1.1 `Mesh_2`（`Refine_faces` / `Refine_edges` /
  `Refine_edges_with_clusters` / `Delaunay_mesher_2`）、Netgen v6.2.2603
  （`occmeshsurf.cpp` 的 `DefineTangentialPlane` / `ToPlane` / `FromPlane` / `Project`）。

> **设计原则**：「在 UV 里做 CDT」和「三维网格质量好」是**两个必须分别验证**的条件。
> 一般变度量下不能对每次翻边任意更换度量，然后继续引用固定欧氏 CDT 的终止结论。

### 2.2 表面三角面片的 8 步流水线

（`ARCHITECTURE.md` §算法，逐条翻译成可执行描述）

| # | 步骤 | 做什么 | 关键点 |
|---|---|---|---|
| 1 | **预算与自动尺寸** | 校验输入与预算，用几何包围盒定自动尺寸 | `targetSize = 对角线 × 0.025`，`minSize = 0.1 × targetSize` |
| 2 | **共享棱离散** | 每条 CAD 棱只生成**一套**物理节点 | 尺寸按 `min(h, 2sin(θ/2)/κ, √(8δ/κ))` 收紧；闭合曲线至少 4 段；退化棱单独处理 |
| 3 | **wire 走向与 p-curve 分支** | 在每个 face wire 上**联合**选择边走向和周期分支 | 面内节点存自己的 UV，同时引用公共三维节点 |
| 4 | **UV 域构造 CDT** | 用图表中心导数构造正定 UV 度量，插点/合法化直接在原 UV 上评价 | 裁剪域用无微扰二维 Delaunay + 锁定约束的凸四边形翻转；共线约束展开为子段链；域标记沿邻接传播、跨外环/孔翻转奇偶 |
| 5 | **三维判据驱动细化** | 按映回三维的边长、偏差、法向变化、质量、翻折检查 | 超长边/大法向跨度优先二分；二分后**立即**从新点一环传播 Lawson 翻边恢复 CDT |
| 6 | **共享边反馈** | 检查细化点是否侵入约束棱直径域 | 登记原曲线新切分参数 → `CadBoundaryRegistry` 只让该棱及关联面失效，无关面复用已验证结果 |
| 7 | **输出与相交检查** | 按 CAD 面统一方向输出，检查边关联/方向/约束/BVH 相交 | 检测到穿越且仍有可分辨近似误差 → 按误差一半收紧相关面偏差，重离散共享棱并重建关联面 |
| 8 | **后置质量优化** | 固定全部共享裁剪/缝/极点节点，做受限翻边与内部节点移动 | 移动用邻点 UV 均值 + 节点处 D1 度量映回 UV 的切向位移；要求局部最坏值下降；失败**回滚**到已接受几何网格 |

### 2.3 三个核心数学点

**(a) 局部度量 —— 把"三维各向同性尺寸"映射到 UV 域**

```
J(u,v) = [S_u, S_v]                      // 曲面一阶导数矩阵
M(u,v) = Jᵀ J / h(S(u,v))²               // 正定 UV 度量
```

- 在边端点、中点、候选点和三角形内部**查询局部度量**；尺寸判据用**三维实际弦长**复核。
- 固定预调节（整面中心一个矩阵）只在**规则图表**内有效，**不能用整张 CAD 面中心的一个矩阵代表全曲面**。
- 度量失去秩 / 失真大 / 跨周期时先**切分图表**，人工切分边也要登记共享节点。

**(b) 曲率尺寸收紧**

```
h ← min( h , 2·sin(θ/2)/κ , √(8δ/κ) )
```

`κ` 由局部 D1 度量中**单位物理长度的法向导数**的最大奇异值估计。这是**采样估计**，
允许突破 `minSize` 并报告具体面/棱与估计值。`θ` 默认 30°，`δ` 默认 `0.1 × targetSize`。

**(c) 二维符号谓词**

- `double` 快速过滤 + **浮点展开回退**；有限输入在中间计算不溢出/下溢时保留精确符号。
- **共圆用稳定 ID 决胜**，绝不移动 CAD 输入点（CAD Delaunay 不微扰 UV）。
- 三维相交是**容差检查**（不是精确判定）；三维四面体谓词另有 filtered/exact + SoS。

| 模块 | 职责 |

| `MeshSizeField` | 三维标量尺寸场，**独立于 UV 和 OCC**，供表面/体网格共用 |

### 2.5 四面体核心的原理链

```
validateVolumeBoundary
  → delaunay3D                        (Bowyer–Watson 增量插点 + orient3dSoS 定向)
  → enforceSurface3D / recoverVolumeBoundary   (约束面/边恢复)
  → extractVolumeDomain               (屏障 + 邻接奇偶分类，处理凹体/空腔/分离域)
  → ruppertRefine3D                   (半径-边比 + 尺寸驱动细化)
  → smooth3D                          (固定边界的 Laplacian + 最小二乘)
  → 边界/域/质量复验
```

各算法角色：

- **`Delaunay3D`**：增量插点。构造阶段在**归一化坐标**（量级 ~1）下用 `orient3dSoS` 定向。
- **`Constrained3D`**：约束恢复。这是**最重、也最容易出问题**的一环 ——
  走的是 *almost Delaunay* 路线（用插点把缺失的边界"逼"出来，过程中**不维持** Delaunay 性）。
  手段包括：保护球（edge protection）、**back-out 退让**、**段中点分裂**、约束面**屏障**。
- **`Ruppert3D`**：按"外接球半径 / 局部目标尺寸"挑坏单元，插外心；受保护段用**直径球**作为禁区。
- **`Flips3D`**：`flip23` / `flip32` + Lawson `restoreDelaunay`。
  **试翻 + 只接受严格改善**（见坑 A6）。
- **`Smooth3D`**：固定边界节点的 Laplacian + 最小二乘平滑。

### 2.6 质量指标体系：为什么必须双指标

| 指标 | 公式 / 来源 | 角色 | 判定 |
|---|---|---|---|
| `minSICN` | Gmsh 定义 | **哨兵** | < 0 → 翻转单元，禁止导出 |
| `minDetJac` | 同上 | 哨兵（与 SICN 互备） | < 0 → 翻转 |
| `gamma = 3r/R` | 正四面体 = 1 | 主指标 | < 0.3 计入"待优化" |
| 最小/最大二面角 | 自算（4 对面法向夹角） | **sliver 复核** | < 10° 或 > 170° 告警 |
| `radius-edge ratio ρ` | 外接圆半径 / 最短边 | 表面质量 | 目标 `√2` |

**核心结论**：radius-edge 比抓整体形状但**抓不住 sliver** ——
薄片单元 ρ 可以低到 0.707（看起来"很好"）却二面角 ≈ 0。所以**必须尺寸比 + 角度双指标搭配**。
另外 Jacobian 类指标（SICN / 条件数）是**唯一能可靠检出翻转单元**的指标，而求解器对
"正 Jacobian、朝向一致"是硬性要求。

> 附带的坑：Gmsh 的**生成优先级**用的是 `radiusNorm = 2`（外接圆半径 / 局部目标尺寸），
> 和本项目的 **√2（外接圆半径 / 最短边）** 是**两个不同的量**，不能把两个阈值等同。

## 3. 踩过的坑

### A. 路线与理论层（最贵、最隐蔽）

#### A1. 把"保证 CDT 存在性的预处理"当成了"恢复断边的手段"

Shewchuk 论文 §3 的定理是：*若 PLC 是 edge-protected，则它有 CDT*。
保护球是**为了让 PLC 满足这个前提**的预处理，**不是**把断边变成网格边的手段。
项目最初把它当后者用 —— 这是**第一处根本性错配**。

#### A2. 走了论文明确警告的 "almost Delaunay" 路线

论文 §1 原文的预言：

> *... the Delaunay property is not maintained during these vertex insertions (at least not fully)
> ... One consequence is that **provably good Delaunay refinement procedures cannot be guaranteed
> to work correctly**. ... they are also **in danger of creating very short edges**, or inserting
> many more vertices than necessary ...*

`insertConstrainedPoint` 正是这条路线。论文列出的三个推论在本项目**全部命中**：
细化不可保证（`Ruppert3DTest` 用例 3 不收敛）、过短边（`cube10.stl` 的 `minSICN = 0`）、
多余顶点（保护球 36 个点纯浪费）。
`cavity volume not conserved` **不是偶然失手，是这条路线的理论宿命**。

**观测到的具体形态**（人工病态 PLC 实测）：

```
[iter 2]     split (9,10)  len=2        pending=8
[iter 19500] split (36,19526) len=0     pending=19506   ← 零长边！
```

每轮都"成功"插点，但 `pendingEdges` 从 8 单调膨胀到 ~19500，边长退化到 `1e-12`~`1e-5`，
打满 20000 轮上限、耗时 12.7 s，**最终仍失败**。根因：cavity 重建不维持 Delaunay 性，
每次细分都破坏先前已满足的边，因此**不存在有限固定点**。

#### A3. grazeable 过滤：立方体用例下保护球【一个点都不该插】

论文 §3 引入 *grazeable*：**旋转顺序下内角 ≥ 180°，或所在面数 < 2** 的段。
只有 grazeable 段需要强 Delaunay，**非 grazeable 段被当作不存在**。

立方体每条棱只有 2 个面，内角 90° < 180° → **非 grazeable**。
论文原话：*"in a regular complex of cubical cells, no segment is grazeable."*

实测对照（决定性验证）：

| | segments | grazeable | candidates | cube.stl 结果 |
|---|---:|---:|---:|---|
| 修复前 | 18 | **18**（全错） | 36 | **FAIL** — `(49,115)`/`(49,135)` 体积不守恒 |
| 修复后 | 18 | **0** | 0 | **PASS** — 与关闭开关逐位一致 |

**36 个点全是多余的，而且正是它们把网格搞坏了。**

#### A4. `insphereDet` 没做符号扰动 → 五顶点共球时判据失效

论文 §9：CDT 构造算法对数值误差比大多数几何算法**更敏感**；五个及以上顶点共球会导致
gift wrapping 失败，除非退化被小心处理。推荐**精确算术 + 符号扰动（SoS）**。

立方体（8 顶点）上"五顶点共球"极易发生（如 2×2×1 的四个角 + 任一其他点）。
项目虽有 `orient3dSoS`，但 `insphereDet` 用的仍是带容差的浮点判据（`> -1e-6`），
**未做 SoS**。修复：`Constrained3D.cpp` / `Flips3D.cpp` 统一改用 `insphereSoS`。

#### A5. 插入失败应该"退让 + 段中点分裂"，而不是直接报死

论文 §8 的原文要求：

> *a [Delaunay] mesh generation program should **test for this possibility, and back out when
> vertex insertion cannot succeed**.*
>
> *... handles this difficulty by considering the **diametral sphere** of each segment to be a
> **protected region**. Any effort to insert a vertex on or inside the sphere is **thwarted**;
> instead, **the segment is split at its center**, and the two resulting subsegments have smaller
> diametral spheres. Thus, every subsegment is kept strongly Delaunay at all times, and **the
> mathematical integrity of the CDT is never broached**.*

项目原来做的是"插入失败 → 直接报死返回 false"。修复后改为 back-out：
保护球点失败 → 改用**段中点**；细分中点失败 → **移出**待处理列表继续。

实测（含凹棱 reentrant edge 的病态 PLC，内角 270° → grazeable → 保护球确实生成）：

```
[grazeable] segments=10 grazeable=8      ← 凹棱被正确识别
[protect]   candidates=16
[backout]   protect point on seg (10,11) failed: cavity volume not conserved
[backout]   protect point on seg (11,8)  failed: ...
[backout]   protect point on seg (11,10) failed: ...
[protect]   ok=13 fail=3 ends=13 validate=1   ← 3 次退让，网格仍合法
validate=1  vol=4.000000                  ← 全程体积守恒
```

注意 `diff/tol ≈ 10⁸`（如 `diff=0.148 tol=1.78e-09`）—— 是**真实几何退化**，不是浮点噪声。

#### A6. ★ 3D 翻转修复会**恶化** Delaunay 性（2D 有保证，3D 没有）★

2D 的 Lawson 翻转**保证**每次 incircle 翻转都严格改善 Delaunay 性，故必然终止于
Delaunay 三角化。**3D 没有这个性质** —— 3D 翻转图存在**环**，单次 `flip23`
可能让违规数**增加**。实测（立方体六面各加 3×3 规则格点）：

```
tets=130  初始违规面=61
restoreDelaunay flips=37  恢复后违规面=90      ← 单调恶化
```

逐面诊断确认**单个 flip 的合法性判据没问题**（16 次 `degenerate new tet`、
2 次 `volume mismatch`，实测 `rel=0.889`/`rel=0.25` 是**真实重叠**而非浮点噪声），
**问题在"该不该翻"**。

修复：把 `flip23` 当**候选**，在副本上试翻，比较全局违规数（`countLocalViolations`），
**只有严格减少才应用**：

```
修复前：flips=37  违规 61 → 90   （恶化）
修复后：flips=1   违规 61 → 60   （改善，且保证不恶化）
```

同一改动对 `Smooth3DTest`：翻转数 `75 → 29`，而 `minDihedral / slivers / worstRho`
**完全不变** —— 被剔除的 46 次翻转是**纯空转**。

#### A7. 凸 + 共球点集是本质退化（球面 5254 条约束边恢复不了）

球面离散点**全部落在凸包上且共球** → Delaunay 剖分不唯一、腔体判定处处平局。
`delaunay3D` 用顶点索引打破平局得到的边界三角剖分与输入剖分**几乎处处不同**
（同一批点、同一批面数，但近共面四边形的**对角线取向不同**）。

这类差异**只能靠翻转（对角交换）消除，中点细分做不到** —— 细分只是把断边换成两条更短的断边。
（旁证：`MESHSTUDIO_DEBUG_BACKOUT=1` 显示 158 次退让全是 `cavity volume not conserved`
且 `volNew > volCav`，如 `volCav=12.3925 volNew=12.4966`，相对 +0.8% —— **重叠**特征，
说明屏障开启后 cavity 对 m 不再满足星形性。）

**根治方向**：先插内部 Steiner 点，或改用"边界优先"的构造顺序，
而不是"先 Delaunay 全部表面点，再恢复约束面"。

#### A8. 局部翻转路线当时不可用（基础设施缺失）

`recoverEdgeByFlips` 每次翻转尝试都要**全扫描一遍四面体**（O(T)），
单次调用即 O(maxFlips × T)。`ball` 上 T ≈ 2.6 万，跑 200 s **一次插入都没发生**。

**修法（已规划）**：把 `m_edge` 的值从"引用计数"扩展为 `{refcount, 一个所属 tet}`，
再沿该 tet 绕边**扇面行走**（用既有面/邻居哈希，O(度) 即可枚举含该边的全部四面体），
把复杂度从 O(maxFlips × T) 降到 O(度)。

### B. 数值与谓词层

#### B1. 谓词不一致 → 假阳性 `tet not right-handed`

**现象**：`ball.brep` 上 `delaunay3D` 报 `mesh invalid: tet not right-handed`。

**量化**（21824 个四面体）：

```
正 21823 / 零 0 / 负 1
负者 |det| = 3.19e-12 ；全体 |det| 均值 2.275、最大 5.175e+02
相对量级 6.2e-15  → 纯浮点噪声，不是真翻转
```

**根因**：构造阶段（`insertPoint3D`）在**归一化坐标**（量级 ~1）下用 `orient3dSoS` 定向；
`validate()` 在**还原后的原始坐标**下用**朴素 `orient3dDet`** 判符号。
行列式随缩放按 `s³` 变化，对近退化薄片其符号完全由浮点误差支配 ——
**两个坐标系下可以给出相反符号**。这就是论文 §9 强调的"exact arithmetic + 符号扰动"同类问题。

**修法**：两处统一改用尺度相对的 `orient3dEps(coordMag4(...))`（`= 64·2⁻⁵²·s³`），
与 `orient3dSoS` 内部判定退化用的是**同一个界**。

#### B2. 绝对常数阈值 vs 尺度相对阈值

`pruneDegenerateTets` 的退化阈值是**绝对常数** `1e-12`：

- 单位立方体（|det| ~ O(1)）合理；
- `cube2.stp`（坐标 500~3000，|det| ~ O(1e9)）**形同虚设**；
- ball 的噪声薄片（3.19e-12）恰好卡在 `1e-12` **之上被漏检**，随后被 `validate` 报成假阳性。

同类：`Flips3D` 里硬编码的 `1e-8` / `1e-6` 也是尺度相关的。

#### B3. ★ 反例：有一处 `1e-9` **不能**顺手改成尺度相对 ★（勿再改）

`insertConstrainedPoint` 里「与 m 共面的边界面」的跳过阈值是绝对常数 `1e-9`。
它看起来和 B1/B2 是同族问题，理应改成 `orient3dEps(sc)`。**实测结果相反**：

| 判据 | `ball.brep` 未满足约束边 |
|---|---:|
| 绝对 `1e-9` | **5254** |
| `orient3dEps(sc)` | 6717（**更差**） |

**原因**：两处判据**语义不同**。
- 「m 是否落在 nt 的面上」（决定 cavity 是否吞该 tet）—— 尺度相对是对的；
- 「这个边界面能不能**省略重建**」—— 省略的**代价**由紧随其后的体积守恒判据精确度量，
  阈值放宽只会让 cavity 边界上的"洞"变大 → 更多体积失配 → 更多退让。

**结论：保持 `1e-9`。已在代码注释里留档，避免后人"顺手修"。**

#### B4. 二维谓词原来是 `double` 裸用

`findings.md`（2026-09-30 源码状态）：`Ruppert2D` 只接受单个简单闭环；
`Constrained2D` 的约束恢复对共线/非凸情形有局限；**二维谓词当前使用 double**。
修复：加入**误差过滤 + 浮点展开回退**；共圆用**稳定 ID 决胜**，不移动 CAD 输入点。

#### B5. 1e-17 级的坐标差会让"显示/连接"失败

EMStudio 共形边的显示问题里，8 个顶点位于近共面位置、原始顶点离网格平面只有约 `10⁻¹⁷`，
导致"画不出来"。教训：**容差判断和"末位浮点差"是两回事** ——
数值上等价不代表下游渲染/连接会认为它们相等。

#### B6. 测试测了一个与实现**不同**的判据

`Flips3DTest` 的违规计数器原先用 `insphereDet(...) > 1e-9`（带容差的朴素谓词），
而实现内部用 `insphereSoS(...) > 0`。实测同一退化输入：
**朴素谓词只看到 2 个违规，SoS 谓词看到 61 个**。

统一到 `insphereSoS` 后，新增用例 4（退化输入）把"不恶化"钉成硬断言 ——
该用例在未加护栏时会因 `61 → 90` 而失败，是一道**有效**的回归护栏。

### C. 几何与拓扑建模层

#### C1. STEP/IGES/BRep 不含三角面片

见 §1.2。这不是"读文件时顺手做的"，而是**必须的一步**。

#### C2. 逐面离散的共享棱必须缝合

`BRep_Tool::Triangulation` 是**逐面**的：每个面有独立的 `TopLoc_Location` 与顶点数组，
相邻面在共享棱上的顶点**只是近似相等，不保证 bit 相同**。不缝合的话，
一条棱会被 4 个面共享，`isWatertight` 直接判不水密，**STEP 路径根本走不通**。

#### C3. `weldSurfaceMesh` 的两个真实缺陷

| 缺陷 | 症状 | 修法 |
|---|---|---|
| **只查精确格子、不探邻格** | 距离 < tol 但被格边界分开的点**静默不合并** | 扫 **3×3×3 邻域** + 真实欧氏距离判据 |
| **坐标量化成 21 位整数**（偏移 1048576） | 有效范围仅 `±1048575·tol`；引擎 `tol = diag·1e-7` → 范围仅 `±0.105·diag`，**大坐标全部被钳到同一格子**；负坐标被 clamp 到 0 | 改用 `floor(v/tol)` 的 **64 位格子坐标**，无偏移、无钳制 |

第二个缺陷的实际影响：`cube2.stp` 坐标是 `x,y ∈ [500,1500]`、`z ∈ [2000,3000]`（diag 1732），
旧实现会把 **24 个顶点全部塌成 1 个**；`ball.brep` 坐标含 `[-11.93, 11.93]` 负半轴，同样塌陷。
修复后：`cube2.stp: 24 → 8` 点；`ball.brep: 4410 → 3850` 点（合并 560 个重复点、
剔除 3 个退化三角形）。

#### C4. 周期缝的 p-curve 分支必须在**整条 wire** 上联合选择

周期面缝边**不能**由棱的正反方向单独决定 p-curve；必须在整条 wire 上**联合**选择走向和分支，
保持节点连接与 UV 连续。

#### C5. UV 坐标混合了角度和长度 → 裸 UV 欧氏 CDT 会产生**三维长边**

OCC 参数域里，U 可能是角度、V 可能是长度。直接在裸 UV 上做欧氏 CDT，
Delaunay 判据看到的"长度"和三维实际长度不是一回事 → 产生三维长边。
修复：用**图表中心导数度量**做 Delaunay 插点/合法化，**原 UV 保留**供 CAD 查询及结果标签。

#### C6. 输出必须按 CAD face 的**统一方向**排列

逐三角形按法向翻转会**掩盖映射翻折**并破坏同面邻接。翻折必须参与细化/失败检查，
不能靠"事后按法向翻转"糊过去。

#### C7. 固定度量 vs 局部度量

Gmsh 用**局部曲面 D1** 建度量，本项目首版用**整面中心固定度量**。
一般变度量下不能对每次翻边任意更换度量、然后继续引用固定欧氏 CDT 的终止结论。
（`findings.md`：`improvePhysicalQuality` 的翻边在两片均达标时跳过、
移动在整个一环达标时跳过 —— 所以**主优化明确以"消除超标"为目标，不能声称已主动优化所有合格片的形状分布**。）

#### C8. "重心侵入约束直径域"作判据 → 过度细化

单纯以"重心侵入约束直径域"判断共享棱分裂会**过度细化**。
正确条件：**棱段本身违反当前局部尺寸/几何条件**，或 UV 裁剪弦相交，
才重建公共边和面。

#### C9. 矩形两侧分段不匹配 → 中心扇形初始化 → 30971 次翻边

面 15 触发局部翻边护栏：**30971 次翻边、1029 三角形**。
记录证明 30971 个四点组**均只翻一次**，未见谓词矛盾或来回翻转 ——
根因是**非匹配边分段的中心扇形初始化**引起大量合法翻边。

修法：改用**两侧节点顺序连接**并保留上下边所有约束；直接通用 CDT 初始化会造成
已有窄条的近共线边恢复失败，所以不能简单换掉。

#### C10. 延迟恢复 CDT → 翻折循环

**现象**：面 16 / 棱 40 反复翻折切分；切分区间从 `[32.571144,32.639679]`
缩到 `[32.622512,32.622516]`（约 4e-6 参数宽）**仍要求切分**。

**根因**：失败片的祖先来自反复内部二分；**恢复 CDT 被延迟到几何判据全部通过之后**，
导致点不断靠近同一条 UV 直线，形成极薄翻折片循环。

**修法**：**每次二分后立即局部合法化**（从新点一环传播 Lawson 翻边），
并让二分事务检查方向/邻接。源 face 9 和 faces 15、16 的原失败用例随即通过。

#### C11. 相交检查误报合法共边 / 共点

局部队列验证发现：**合法共边接触**与**浅交角下的公共点插值残差**被误报为相交。
修复后仍拒绝共面重叠、重复面片和穿过共同顶点的内部交叉。

#### C12. 真实球面间隙 0.05 的面片穿越 → 单面偏差不够

球面片相交**确有穿越**：外/内 CAD 球半径 `12 / 11.95`，同中心，间隙 `0.05`。
独立**精确有理数**测试得到严格内部交点 —— **不能扩大相交容差，也不能只检查单面偏差**。

修法：检测到穿越且仍有可分辨 CAD 近似误差时，**按其误差的一半收紧相关面的偏差**，
重新离散关联共享棱并重建所有关联面。平面零近似误差的相交则**立即拒绝**。

#### C13. 独立部件策略 ≠ 公共剖分

`phone` 是 **132 个实体**的装配体。用户明确要求"保留部件与接触界面"、"干涉也各按各的生成"。
所以表面引擎用 `AssemblySurfacePolicy::IndependentBodies`，核心默认仍是 `RejectBodyOverlap`。

**坑在于**：独立部件**没有**在接触两侧建立一致公共剖分，
因此**表面结果不能直接作为无重叠的多区域四面体边界**。这个限制必须显式写进文档，
不能靠放宽相交检查"解决"。

#### C14. 窄带：尺寸来源与新增边下限的冲突

`phone` 的真实窄带（face 172/181 各 542 条残差）根因是：
**共享曲率边的必要密采样**与**质量插点的 min 下限**互相冲突。
直接读已验收面连接发现：细侧 `.4296875`、对面粗侧 `1.71875`、宽 `.5` 的错位片，
**没有满足原局部条件的单次翻边**。
最终靠"对面粗 CAD 段中点对齐 + 共享队列同步"把 542 → 160，但**最差片反而从 1.74 变 1.87**
（明确的局部回退，已在报告里如实披露）。

### D. 性能与复杂度层（收益最大的一层）

#### D1. ★ O(T) 全网格校验被放进了逐元素热循环 → O(n·T) 二次方 ★

`validate()` / `checkFaceHash()` / `hasEdgeAny()` 都是 **O(T)**，却被放进了**三处逐元素循环**：

| 位置 | 原状 | 修法 |
|---|---|---|
| `Delaunay3D` 插入循环 | 每插一点 `checkFaceHash()`（4T 次哈希查找） | 诊断开关（默认关），末尾 `validate()` 兜底 |
| `insertConstrainedPoint` 收尾 | **每次插入** `validate()` | 诊断开关；`enforceSurface3D` 收尾一次 |
| `Ruppert3D` 主循环 | **6 处**逐轮 `validate()` | 诊断开关；`ruppertRefine3D` 收尾一次 |
| `tryRemoveSliverByFlips` | 循环体内重算 `meanEdgeLength3D(m)` → **O(T²)** | 尺度量提到循环外 |
| `TetMesh3D::hasEdgeAny` | **O(T)** 全扫描 | 新增**边哈希** `m_edge` → **O(1)** |

统一开关：`MESHSTUDIO_VERIFY_EACH_STEP=1` / `MESHSTUDIO_DELAUNAY_VERIFY_EACH_STEP=1`。

**实测收益**：

| 项 | 前 | 后 |
|---|---:|---:|
| `Delaunay3DTest` | 3.89 s | **0.30 s** |
| 单元测试合计 | 12.76 s | **7.58 s** |
| `ball.brep` 全链路 | **>135 s 仍未完成** | **25.7 s**（且给出明确诊断） |

> **边哈希**是唯一的**数据结构级**新增：`m_edge: key(无向边) → 引用计数`，
> 与既有 `m_face` 同构，在 `addTet` / `removeTet` 中同步维护。
> `validate()` 现在会**重算一遍引用计数比对** —— 因为这张表一旦失同步，
> 约束边恢复会**静默**判错，比"慢"危险得多。

#### D2. ★ 每次几何查询都重建 OCC 适配对象 ★（最大单点收益）

**现象**：`move.stp` 核心耗时 **99.82 s**。

**根因**：本机 OCC 源码证实 `BRepAdaptor_Surface::Initialize` 默认会**重算裁剪 UVBounds、
遍历面上棱**。当前适配器**每次点/法向/D1/范围查询都重建曲面适配对象** ——
按接口次数推得 **1 397 991 次构造**。

**修法**：缓存每面 `BRepAdaptor_Surface`、常规棱 `BRepAdaptor_Curve`、端点/范围及
`(face,edge,branch)` p-curve；保留 Location、Restriction=true、反向法向和退化棱。

**实测**：`move.stp` off 三轮中位数 **99.82 s → 4.48 s（约 22.3×）**，
且**输出指纹完全一致**（98584 片 / 48690 点，坐标/连接/CAD 标签/逐角 UV 逐位相同）。

后续 C/D/E/F 阶段继续压到 **2.83 s**（累计约 35×）。

#### D3. 每次插点复制整面网格 + 每轮全域 BFS 分类

`findings.md`（性能源码对照）：CAD 插点/分边**仍复制完整面网格并全面校验**；
**每轮重新全域 BFS 分类**；整表查重/邻片查找。

修法：`Mesh2DTransaction` 局部事务（记账局部三角形/邻接/半边节点/点片长度，
失败逆向恢复）+ `SurfaceDomainState` 局部域标签（只继承源片标签、检查变化区域一环奇偶）。

#### D4. 翻转恢复 O(maxFlips × T)

见 A8。

#### D5. 发散判据选错了

旧判据是「待处理条目数 > 初始 + 64」。方向对，但**判据选错**：
每次**合法**细分都会让条目数 +1（1 条边换成 2 条子边），
大输入在**正常细分途中**就会被误判。
实测 `ball.brep`（11538 条约束边）第 67 次细分即触发 `pending grew to 11603 (limit 11602)`。

**正确判据**是**未满足边数是否在进展**：
- 收敛路径：每细分一次就有边变成网格边 → `unsatisfied` 单调下降；
- 发散路径：只插点、`unsatisfied` 长期不降。

新实现：每 2000 轮统计一次 `unsatisfied`，连续 3 个窗口未刷新历史最好值即判发散；
`maxEdgeIters` / `kMaxPending` 改为与初始规模成比例（`max(旧下限, 4×初始)`）。

**护栏效果**：`12.7 s → 0.56 s（23×）`，且报错信息从
含糊的 `did not converge after 20000 subdivisions` 变成**可诊断**的：

```
edge recovery diverged: pending constraint sub-edges grew to 75 (limit 74);
almost-Delaunay route cannot resolve this configuration
```

#### D6. CDT 细分缺"约束面屏障"（真缺陷）

`recoverConstraintEdges` 的细分循环调用 `insertConstrainedPoint` 时，
`excludeFaceKeys` 传的是**空集** —— 而同一文件里保护球阶段的注释明确写着
"若传空集（这是最初的错误写法），cavity 会横穿约束面扩张……边界被破坏"。

**后果**（`MESHSTUDIO_DEBUG_CDT=1` 的 `[cdt-split]` 直接抓到）：

```
(4,87)   -> (4,3854)=1 (3854,87)=1     首次两个子边都成立
(4,3854) -> (4,3856)=1 (3856,3854)=0   第二子边没建立
(4,3856) -> ...                        随后又回到 (4,3856) 再细分
```

即：**刚建立的子边被后续插入破坏**，`pending` 单调增长、永不收敛。

| 输入 | 屏障关 | 屏障开 |
|---|---|---|
| `cube.stl` | 10/11/20, minSICN=0.577350 | **逐位一致** |
| `cube10.stl` | 103/405/124 | **逐位一致** |
| `ball.brep` 未满足约束边 | 11538（零进展，无限发散） | **5254**（恢复 6284 条 ≈ 55%） |

#### D7. 相交阶段独占 26.6 s

观察版 `phone` 相交阶段 **12 次、独占 26.59 s**，占生成 56.51 s 的重要部分。
已有 OCC 关系缓存，所以不是靠再加 CAD 布尔缓存解决。
修法：**复用未变部件的已通过相交结果**，只检查受影响部件，结束前再全量核对相交及关系集合。
（独立默认严格入口继续全量。）

#### D8. 顺序很重要：先缓存/事务，再并行

性能计划被拆成 A–F 六阶段，G（算法改进）/H（并行）**后置**：

```
A 计量（可关闭观察接口 + 基准 + 独立审计具名参数）
B 求值（缓存 OCC 适配对象与原参数）        ← 22× 收益在这
C 局部事务（Mesh2DTransaction）
D 局部域标签（SurfaceDomainState）
E 版本化队列（SurfaceRefinementQueue）
F 完整验收（GUI / 取消 / 预算 / Gmsh 对照）
```

实测：A 99.82 s → B 4.48 s → C 2.97 s → D 2.66 s → E 3.02 s → F 2.83 s。
**注意 E 并不比 D 快** —— 完整测量与新候选顺序有代价，报告如实记录，没有粉饰。

### E. 质量指标与优化策略层

#### E1. 生成优先级 ≠ 形状底线

见 §2.6。Gmsh `MTri3` 默认 `radiusNorm = 2`（外接圆半径 / 局部目标尺寸），
本项目 `√2` 是**外接圆半径 / 最短边** —— 不是同一个量。

#### E2. 主优化只在"超标"时动

`improvePhysicalQuality` 的翻边在**两片均达标**时跳过，移动在**整个一环达标**时跳过。
所以主优化**明确以"消除超标"为目标**，**不能声称已主动优化所有合格片的形状分布**。
（2026-10-05 才补上"合格片优化"：末尾一次最多 4 轮，`q = 4√3·A/(a²+b²+c²)`，
要求局部最差 radius/edge、最低 q 不恶化、平均 q 严格改善。）

#### E3. `min` 被误当成所有旧节点/边的**硬**下限

**反例**：禁止已有短边继续改善的试验，使凹球由 **23 个残差变成 195 个**，已撤回。

**正确语义**：常规 `min` 是**目标**及**新质量插点**的护栏，
**不是**所有旧节点/边的硬下限。几何/必保特征需要更小时记录来源与实际尺寸。

#### E4. 过强的"改善"规则会误拒绝有效改善

试过"逐项排序都不降"的规则 → **所有有效改善被拒绝**，已撤销。
也试过"最差值和总和都下降" → 独立一环测量找到所有片都达标且边长/方向合法的移动，
但**质量总和略升**，被误拒绝。

**修法**：后置形状优化允许**整个一环达标时总和略升**，
但仍要求**最差值严格下降**且通过几何验收。

#### E5. "仅插入新点后再优化" → 0 插点时优化完全不执行

末尾残差优化挂在"有插点"分支后面，导致 0 插点时**完全不执行**，
宽面最后 1 片无法达标。修正后：宽面最后 1 片达标，最终 0 超标 / 407 点 / 660 片 /
worst `1.4123810633466651`。

#### E6. 质量切分产生的**新短段**会变成新的尺寸源 → 递归加密

**修法**：**固定首次几何采样作为尺寸来源**（`SurfaceBoundarySizeField`），
沿有效面域邻接传播并在插点新增邻接时更新；**质量切分不变成新的小尺寸源**。
粗网格上单跳比例传播也会把很小尺寸过快扩散 ——
改用**有效域邻接的物理路径增长**。

#### E7. 质量新点也可能违反局部下限

`SurfaceQualityPolicy::decision` 原对所有"最短边 < min"的片**禁止质量插点**，
而偏心候选以该短边为等边腰长又**必然触发新增边下限 veto** → 死锁。
修法：用必要条件 `min/(2ρ)` 替代过宽的跳过，并按**新增两腰下限**生成候选。

### F. 工程与流程层（这些坑不致命，但会让结论失真）

#### F1. PowerShell 不加引号的小数会**缩短原生 argv**

发现中间试验与基线的 `criteria` **末位不同** → 撤销同参数比较。
修正：正式六轮采用**基线文件中的实际字符串，全部加引号**，
并要求逐字段与基线完全一致后才报告对照。

#### F2. 主程序 exe 被用户窗口占用 → 链接失败

多次出现"核心/测试目标构建通过，但主程序链接失败"。
**不能宣称新主程序已更新**。报告里必须写清"哪一层构建成功"。

#### F3. 自动窗口测试 ≠ 用户手动验收

项目做了大量 `CadSurfaceGuiTest`（真实 Qt/VTK 窗口生成/取消/保存重开 + 图像检查），
但文档一律标注"**这不是用户手动操作验收**"。这个区分很重要。

#### F4. 有限采样 ≠ 全局误差界

`CadSurfaceQualityAuditTest` 用独立采样布局（每面 16×16 偏移 UV 格点 + 每棱 33 个非中点采样）
核对双向距离，**不复用生成器偏差函数** —— 这已经是很好的独立性，
但结论只能写"**有限采样，不证明全局误差上界**"。

#### F5. 中间试验不能当最终结果

报告里大量标注"中间版本，不能当作最终验收"（如"033331 轮测量中修改了测试文件，
源指纹检查拒绝，本轮作废"）。

#### F6. 诊断只写日志，没有随结果保存

发现 `CadSurfaceDiagnostics` 实际**未随 VTP 保存** → 新往返断言先失败，
补 VTK `FieldData` 字符串数组后才真正可查。

#### F7. 按模型名猜类型

GUI 原按中文模型名识别网格 → **遗漏自研表面并重设尺寸**。
改用 `ModelSummary::isMesh/isSurfaceMesh` 的实际类型标记。
另：缺少单位元数据时**不能仅凭 STEP/IGES 后缀标 mm**。

## 5. 复盘：如果重来一次

### 5.1 技术选型层面

- [ ] **先确认论文的适用范围**。保护球解决的是"CDT 存在性"，不是"恢复断边"；
      平面 PSLG 的终止条件不能直接搬到变度量 CAD 曲面。
- [ ] **明确自己走的是哪条路线，并接受它的代价**。选 almost Delaunay 就要预埋
      "back-out + 段中点分裂 + 发散检测"三个护栏，而不是等它无限细分再补。
- [ ] **grazeable 过滤这类"免做"条件要第一时间接上**。立方体本不该插任何点。
- [ ] **3D 的翻转没有 2D 的单调性保证**。任何"靠翻转改善"的循环都要有"只接受严格改善"的护栏。

### 5.2 数值层面

- [ ] **一套谓词贯穿全流程**：构造、校验、测试必须用**同一个**判据。
      归一化坐标 vs 原始坐标混用会直接产出假阳性。
- [ ] **所有容差都必须是尺度相对的**，除了那些"语义上就该是绝对值"的（如 B3 的 `1e-9`）。
      改之前先问："放宽它会放大什么代价？"
- [ ] **退化输入（共球/共面）要专门造测试**，而且测试用的谓词要和实现一致。

### 5.3 工程层面

- [ ] **先量测，再优化**。A–F 的顺序（计量 → 求值缓存 → 事务 → 域标签 → 队列 → 验收）
      比"直接上并行"有效得多；本项目的 35× 里绝大部分来自最前面的两步。
- [ ] **O(T) 的检查永远不要放进逐元素循环**。要么做诊断开关，要么做增量索引。
- [ ] **"收敛/发散"的判据要选对量**。数量增长可能是合法细分，要看"未满足量是否在下降"。
- [ ] **报告纪律**：有限采样不叫误差界；自动窗口测试不叫用户验收；
      单轮不叫中位数；中间试验不叫最终结果；链接失败不叫已更新。
