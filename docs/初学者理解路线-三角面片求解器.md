## 0. 你其实只需要 4 块数学（而且都只要"够用"）

很多初学者卡住，是因为以为要先学完计算几何教材。**不需要。** 只要下面四件事：

| # | 知识点 | 需要到什么程度 | 项目里对应 |
|---|---|---|---|
| 1 | **叉积 / 有向面积** | 会算 `(b-a)×(c-a)` 的符号，知道正负代表点在左边还是右边 | `MesherTypes.h` 的 `signedArea2` / `triangleArea` |
| 2 | **外接圆 / 外接球** | 知道"过三点的圆"怎么来的，知道**空外接圆准则**这句话的意思 | `MesherTypes.h` 的 `circumcircle` |
| 3 | **浮点误差与符号谓词** | 知道"两个差不多大的 double 相减会丢精度"，所以**判符号**不能直接看正负 | `GeomPredicates.h` |
| 4 | **一点点微分几何** | 知道曲面有一阶导数矩阵 `J = [S_u, S_v]`，UV 上走一小步，三维长度 ≈ `|J·Δuv|`；曲率越大越需要密网格 | `SurfaceChart.h` / `ARCHITECTURE.md` §算法第 2 步 |

**明确不需要**先学：有限元、CGAL、Gmsh 源码、微分流形。
这些等你能把项目跑通、看懂二维部分之后再碰。

### 台阶 1 · 二维 Delaunay（最核心，1~2 天）

**这一级是整个项目的根。吃透它，后面全是它的变体。**

**看**（按顺序，都是小文件）
1. `src/core/mesher/MesherTypes.h` —— 约 40 行有效代码，先认数据类型
2. `src/core/mesher/GeomPredicates.h` —— 只有 20 行，**这是全项目的判定基础**
3. `src/core/mesher/Mesh2D.h` —— 看 `Tri2D` 结构：`v[3]` 是顶点、`n[3]` 是**邻居三角形**
4. `src/core/mesher/Delaunay2D.cpp` —— 重点只读 **`insertPoint`** 一个函数

**核心概念（就三个）**
- **Delaunay 性质**：任何三角形的外接圆里**不含**其他点
- **Bowyer–Watson 空腔插点**：插一个新点 → 找出所有"外接圆包含新点"的三角形 → 挖掉它们形成一个**空腔** → 把新点连到空腔边界 → 完成
- **邻接表**：`n[3]` 让你 O(1) 找到对面邻居，这是后面一切"局部操作"的前提

**跑**

```bash
ctest --test-dir build -C Release -R Delaunay2DTest -V
```

**动手做（强烈建议）**
在纸上画 5 个点，手工跑一遍 Bowyer–Watson，标出每一步删了哪些三角形、加了哪些。
然后再看 `Delaunay2DTest.cpp` 里的断言，对照你的手算结果。

**什么算懂了**
- 能画出"插入一个点后，哪几个三角形被删、哪几个新增"
- 能解释 `n[3]` 里 `-1` 是什么意思（边界，没有邻居）

### 台阶 2 · 约束三角化（CDT）：为什么需要"恢复"

**问题**：Delaunay 只保证**形状好**，它**不保证**"你指定的那条边一定出现在网格里"。
圆孔的边界、零件的棱，都是"我必须出现在网格里"的边 —— 这叫**约束边**。

**看**
1. `src/core/mesher/Constrained2D.h` —— 三个函数就是三件事：
   - `enforceConstraints`：把约束边变成网格边（**恢复**）
   - `expandConstraintEdges`：把约束边**展开成子段链**（因为约束边可能跨过已有顶点）
   - `classifyConstrainedDomain`：判断每个三角形在**域内**还是**孔里**
2. `src/core/mesher/Constrained2D.cpp`

**核心概念**
- **约束边 / 约束恢复**：靠**翻转**（交换对角线）或**插点**，把断掉的约束边"接"上
- **域标记**：为什么"圆孔里的三角形"必须被删掉（不能只靠三角形重心判断，要沿邻接传播）
- **共线约束**：一条直边上本来就有顶点时，必须拆成子段

**跑**

```bash
ctest --test-dir build -C Release -R Constrained2DRobustTest -V
```

**什么算懂了**
- 能解释：为什么"外接圆准则"不保证我的边在网格里
- 能解释：为什么"域分类"不能只看三角形重心

### 台阶 3 · 表面比平面难在哪 —— 参数域与度量

**这是从"平面三角化"跨到"CAD 曲面三角化"的关键一步，也是最容易懵的一步。**

**看**
1. `docs/superpowers/plans/2026-10-01-cad-surface-meshing-revision.md` 的 **§3.1「参数域与局部度量」**（就一页）
2. `ARCHITECTURE.md` 的「算法」第 2~4 步
3. `src/core/mesher/SurfaceChart.cpp` —— 只有 117 行

**核心概念（一个例子就够）**

想象一个圆柱面。它的 UV 参数域是一个**矩形**：`U` 是绕一圈的角度（0~2π），`V` 是高度（mm）。
如果你直接在这个矩形上做 Delaunay，会发生什么？

- 你在 U 方向走 `0.1`，三维里可能只走了 `0.1 × 半径`；
- 你在 V 方向走 `0.1`，三维里就是 `0.1 mm`。

**两个方向的"1"在三维里长度完全不同** → Delaunay 判据被彻底带偏 →
产生一堆**看起来在 UV 里很正、在三维里又长又扁**的三角形。

所以必须引入**度量**：

```
J(u,v) = [S_u, S_v]                 // 曲面一阶导数（OCC 能查）
M(u,v) = Jᵀ J / h(S(u,v))²          // 把"三维各向同性尺寸 h"映射到 UV
```

**一句话**：**UV 域只负责"拓扑"（谁连着谁），"尺寸和质量"必须在三维里量。**

**跑**

```bash
ctest --test-dir build -C Release -R OccCadSurfaceTest_cylinder -V
```

**什么算懂了**
- 能解释"为什么不能在裸 UV 上做 Delaunay"
- 能解释 `M = JᵀJ/h²` 里 `JᵀJ` 在干什么（把 UV 位移换算成三维长度的平方）

### 台阶 4 · 细化（Refinement）：尺寸从哪来、坏片怎么挑

**看**
1. `src/core/mesher/Ruppert3D.h` 的 `Ruppert3DParams` —— **这是最直白的"算法参数说明书"**：

```cpp
double maxEdgeLength   = 1.0;   // 目标最大边长
double radiusEdgeRatio = 2.0;   // 外接球半径 / 最短边，>ρ 就算坏
int    maxIterations   = 300000;// 防止无限跑
```

2. `src/core/mesher/SurfaceQualityPolicy.cpp` —— 108 行，讲"什么片子该被细化"
3. `src/core/mesher/SurfaceRefinementQueue.h` —— 坏片队列

**核心概念**
- **尺寸场**：每一点"应该有多大的网格"，不是常数
- **坏片队列**：维护"当前不满足判据的三角形/四面体"，只处理这些
- **外心插点**：在坏片的外心处插新点（外心是"离三个顶点最远的点"，插它最有效）
- **encroachment（侵入）**：新点如果太靠近某条约束边，会**破坏**约束 → 必须先处理边界
- **终止条件**：`ρ` 和最小角；**尖角处一定达不到，只能当软目标并报告**

**跑**

```bash
ctest --test-dir build -C Release -R Ruppert3DTest -V
ctest --test-dir build -C Release -R SurfaceQualityPolicyTest -V
```

**什么算懂了**
- 能解释"为什么 ρ=√2 是目标值"、"为什么尖角处的最小角一定不达标"
- 能解释"为什么细化要先处理边界，再处理内部"

### 台阶 5 · 三维：从三角形到四面体

**看**
1. `src/core/mesher/TetMesh3D.h` —— 看 `Tet4` 结构，和 `Tri2D` 对比
2. `src/core/mesher/Delaunay3D.cpp`
3. **`docs/references/README-shewchuk-failure-analysis.md` 的 §1~§3** ← ★ **强烈推荐**。
   这是你自己项目的文档，讲的是"为什么三维这么难"，比任何教材都贴切。

**核心概念**
- **空外接球准则**：把"圆"换成"球"，其余一样
- **面哈希 `m_face` / 边哈希 `m_edge`**：判断"这条边/面存不存在"从 O(T) 变成 O(1)
- **★ 2D 和 3D 的本质差别 ★**：2D 的 Lawson 翻转**保证**每次翻转都让网格更 Delaunay，
  所以**一定收敛**；**3D 没有这个性质**，翻转图里有环，翻了可能**更差**。
  这就是为什么 `Flips3D.cpp` 要"在副本上试翻，只有严格改善才应用"。

**跑**

```bash

```

**什么算懂了**
- 能解释"为什么 3D 翻转不保证收敛，2D 保证"
- 能说出"退化"是什么意思（共圆、共球、共面）

## 2. 五个调试开关 = 五台显微镜

这些是项目里**已经写好的**环境变量。它们**不改变算法结果**，只是把内部状态打出来。
初学者用它们比自己加 `printf` 强得多。

| 环境变量 | 打出什么 | 什么时候用 |
|---|---|---|
| `MESHSTUDIO_DEBUG_CDT=1` | CDT 主循环进度、seed walk 步数、细分后子边是否成立 | 想看"约束恢复到底在干什么" |
| `MESHSTUDIO_DEBUG_BACKOUT=1` | 每次"退让"的边 + 原因 + 体积失配数值 | 想理解"失败为什么能安全放弃" |
| `MESHSTUDIO_DEBUG_PROTECT=1` | 保护球候选/成功/失败计数、grazeable 统计 | 想理解保护球（台阶 5 的延伸） |
| `MESHSTUDIO_DELAUNAY_VERIFY_EACH_STEP=1` | **每插一个点**就全网格自检 | 定位"第几步把网格弄坏了"（**很慢**） |
| `MESHSTUDIO_VERIFY_EACH_STEP=1` | 同上，但覆盖全流程 | 同上，范围更大 |

**用法示例**

```bash
cd F:/Code/MeshStudio

# 看约束恢复在干什么
MESHSTUDIO_DEBUG_CDT=1 ./build/Release/TetMeshEngineTest.exe test_data/cube.stl

# 看保护球 + 退让（用球面这种会触发的输入）
MESHSTUDIO_DEBUG_PROTECT=1 MESHSTUDIO_DEBUG_BACKOUT=1 \
  ./build/Release/TetMeshEngineTest.exe test_data/ball.brep

# 定位"第几步坏了"（慢，但信息量最大）
MESHSTUDIO_DELAUNAY_VERIFY_EACH_STEP=1 \
  ./build/Release/TetMeshEngineTest.exe test_data/cube10.stl
```

**为什么这些开关存在？** 因为项目踩过一个坑：
`O(T)` 的全网格自检被放进了逐元素循环，把复杂度从 `O(n·T_avg)` 退化成 `O(n·T)`
（`ball.brep` 从 0.82 s 变成 >135 s 跑不完）。修法就是**改成默认关闭的诊断开关**。
所以你打开它时慢是正常的 —— 那是它在做"每步全身体检"。

## 3. 八个最容易卡住的概念

| # | 概念 | 一句话解释 |
|---|---|---|
| 1 | **Delaunay 不是算法，是性质** | 它是"空外接圆"这个**条件**；Bowyer–Watson、增量插点是**实现它的算法** |
| 2 | **"网格好"有两个独立含义** | ① 形状好（不瘦）② 贴合几何（误差小）。两者会**互相冲突**，必须分开验证 |
| 3 | **UV 域 ≠ 三维空间** | UV 只管拓扑，长度/角度必须在三维里量（台阶 3） |
| 4 | **约束边要"恢复"** | 不是天然就在网格里，要靠翻转/插点把它接上（台阶 2） |
| 5 | **判符号不能直接用浮点** | 两个相近的数相减会丢精度，所以要用**误差界 + 精确回退**（`GeomPredicates.h`） |
| 6 | **"退化"不是 bug** | 共圆、共球、共面是**几何本身**的性质。立方体的 8 个顶点天生五顶点共球 |
| 7 | **多插点不一定更好** | 插点会产生**极短边**，反而让质量崩掉。项目的 `cube10.stl` 就是 `minSICN = 0` |
| 8 | **有限采样 ≠ 数学证明** | 检查了 1000 个点都对，不代表"处处都对"。项目文档里一律写"有限采样，不证明全局误差界" |
