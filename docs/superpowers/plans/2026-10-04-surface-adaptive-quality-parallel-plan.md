## 2. 参数规则：自动推荐、手动值与局部细化

### 2.1 每个几何模型独立保存

拟新增 `src/core/SurfaceMeshSettings.h/.cpp`，负责设置来源、默认推荐和生成前解析，保留 `mesher::SurfaceCriteria` 作为核心算法的数值契约。

建议的数据关系：

```text
模型稳定 ID
  └─ SurfaceMeshSettings
       ├─ 每项参数来源：Automatic / Manual
       ├─ 手动数值：SurfaceCriteria
       ├─ 自动推荐规则版本
       └─ 最近一次生成的实际 SurfaceCriteria 和几何指纹
```

运行时 modelId 映射至持久模型 UUID；文件名、显示名或路径不能单独充当身份。同一文件重复导入也建立独立模型实例。生成结果保存源模型 UUID 和本次实际参数，避免源模型之后改参数导致旧网格记录失真。

### 2.2 首版推荐公式

`D` 为实际送入几何适配器的 CAD 包围盒对角线，长度使用该几何坐标单位。

| 参数 | 自动推荐规则 | 手动行为 |
|---|---|---|
| 最大尺寸 / 基础目标 | `0.025 × D` | 按输入值使用 |
| 最小常规尺寸 | `0.1 × 已解析最大尺寸` | 按输入值使用 |
| 最大几何偏差 | `0.1 × 已解析最大尺寸` | 按输入值使用 |
| 最大法向变化角 | 30° | 按输入值使用 |
| 质量目标 | √2 | 按输入值使用 |
| 边界尺寸渐变率 | 1.3 | 按输入值使用 |
| 节点 / 工作预算 | 各 200000 | 按输入值使用，超预算明确失败 |

这里的“自动”首先解决按模型尺度初始化与重算；不声称这些比例已经是每种 CAD 的最佳参数。曲率和窄区通过局部场影响实际网格，而不是暗中修改用户的偏差/质量要求。

每次打开弹窗预览解析值；每次生成前针对实际输入几何重新解析自动项，并将数值快照记录到日志和输出。先解析最大尺寸，再解析依赖它的自动最小尺寸/偏差。手动项保持不变；若手动最小值超过新的自动最大值，显示冲突并停止生成，不能偷偷截断。

几何未变时自动值稳定。不能只用视口变换后的包围盒计算参数、同时仍按原文件坐标生成；先核对变换至生成的数据链，若两者不一致，报告坐标语义并暂停扩大变换支持范围。

### 2.3 弹窗交互

- 沿用现有 DialogFormFactory、颜色、间距和紧凑数字显示。
- 各长度项提供“自动”状态及当前推荐值；手动编辑只改变该项来源。角度、质量、渐变率和预算继续在原位置设置。
- “恢复默认”恢复当前模型所有表面项至推荐设置；取消不写入设置；生成前校验成功后才保存当前模型设置并开始任务。
- 全精度值用于计算、日志和存储；显示去除多余小数，不能因为打开弹窗就把未编辑值舍入。
- UI 写“模型坐标单位”；尺寸下限说明继续保留必要小特征例外及冲突诊断。

### 2.4 老工程兼容

- `ProjectModelEntry` 增加稳定 UUID、可选逐模型表面设置、表面结果来源及实际参数。
- 缺少新字段的老工程：为每个几何条目分配独立 ID，将原工程表面数值复制为各模型的手动设置，保留旧 `maxSize=0` 的实际允许上限语义。
- 老格式没有参数来源证据，不能猜测原值是自动值，也不能重开工程就重新估算。
- 保留旧工程级字段用于读入迁移，明确新字段优先级；不修改原包，用户下一次正常保存才写入扩展数据。
- 缺少来源的历史网格标为来源未记录，不靠重名匹配关联模型。无效或不支持的设置版本返回明确诊断。

## 3. 凹球与 Gmsh 的对照方法

### 3.1 冻结条件

主模型：`C:/Users/30861/Desktop/conformal/concavaball.stp`。保护模型：`C:/Users/30861/Desktop/conformal/phone.stp`。小模型回归：平面带孔、立方体、圆柱缝、球面极点、尖角及窄域。

记录原 CAD SHA256、接受的容差修复记录、源代码指纹、Release 配置、Gmsh 版本/选项、解析后的参数、线程数及输出指纹。测试期间不编辑被测源码；结果存入独立临时目录，原文件不修改。

先比较自研串行、Gmsh Delaunay（5）、Gmsh Frontal-Delaunay（6）。曲率关闭及明确曲率设置分别记录，不能把开启曲率的结果混称默认结果。

### 3.2 分开做两组比较

**相同用户限制：** 最大尺寸、尺寸场最小值及单位一致；Gmsh 没有与本项目完全相同的偏差/法向选项语义，统一用独立 OCC 审计测量两套输出是否满足同一要求。`MeshSizeMin` 是目标场下限，不是每条三角边的硬下限；仍需报告实际短边和必要特征例外。

**接近面片数量：** 以当前凹球约 13966 片为参考，仅扫描并记录 Gmsh 尺寸/曲率选项，将片数差控制在 ±10% 后比较形状质量和局部密度。必须同时满足相同的独立几何采样要求；若无法满足，报告无法配对，不强行下结论。

保持各套参数完整公开。不把面片更多、误差更松或最小尺寸语义不同造成的改善归因于算法。先做一轮定位，最终选定配置再各做三轮串行计时，避免无目的参数穷举。

### 3.3 统一指标

- 有限坐标、退化片、约束保留、共享棱一致、闭合/方向、同部件自交、部件标签及关系记录。
- 三维 `R/最短边`：最大值、P50/P95/P99、超过 √2 的数量。
- 每片最小角：最小值、P1/P5/P50，以及低于 25°、30°的占比。
- 三角形形状指标 `q = 4√3 A/(a²+b²+c²)`，等边为 1：P1/P5/P50。
- 每片三条边的最大/最小之比；共享边两侧局部平均尺寸的跳变；实际边长与局部目标尺寸之比。统计按 CAD 面及极点/缝/边界邻域分别给出，避免用全局边长方差惩罚必要的曲率加密。
- CAD→mesh 与 mesh→CAD 双向距离、法向变化，沿用全部 CAD 面及窄区补采样；说明采样位置与数量。这些是测量结果，不是全局误差证明。
- 导入、适配器准备、边采样、面构建/细化、质量优化、验收、保存分阶段计时；峰值内存和工作预算同时记录。
- 用同一视角/缩放、相同边线与质量着色展示凹球整体、凹面交界和极点。标注截图对应输出指纹，保留可重新打开的网格。

复用 `CadSurfaceQualityReport.h`、`CadExternalMesh.h`、`CadSurfaceQualityAuditTest.cpp`。外部面身份通过已有几何签名核验；签名歧义返回失败，不能直接用 Gmsh 面号作为 OCC 面号。

## 4. 自研质量改进路线

选择保留参数域 CDT 拓扑，增加物理尺寸场和前沿式插点候选。Gmsh 的 Frontal-Delaunay 是机制参考；不接入其生产网格生成器，也不将参考机制称为已实现。

### 4.1 先定位布局差异

- 对凹球逐面统计差异，检查极点/缝附近、固定边界、内部插点候选及优化停止条件。
- 分别记录候选被最小尺寸、偏差、法向、方向、空腔拓扑或预算拒绝的次数，使用有上限的诊断。
- 自适应推荐仅影响尺度；如果相同条件下 Gmsh 更好，继续追查局部目标与插点策略，不以让用户不断调参数作为修复结果。

### 4.2 建立贯穿边与面内部的局部物理尺寸查询

- 复用 `SurfaceChart` 的曲面度量、曲率估计和 `SurfaceBoundarySizeField` 的传播缓存。
- 拟新增 `SurfaceSizingPolicy.h/.cpp`：综合基础目标、用户尺寸场、曲率/偏差/法向尺寸、固定 CAD 特征和已核实的同面窄区宽度，统一供边采样、内部插点及质量优化使用。
- 曲率尺寸公式仍作为估计，插点后必须按实际三维三角形重新量偏差与法向；极点/不可解析导数使用现有专门图表处理或明确诊断，不返回无穷大并静默跳过。
- 同面窄区只接受由不相邻裁剪边/局部边界得到且通过域检查的来源，排除共享端点和相邻边造成的假零距离。跨部件接触不作为零尺寸来源。
- 必要特征可低于常规 min，但源具有 CAD 棱/面、位置及原因；质量新点不能递归成为无限缩小尺寸的依据。
- 分别验证平面、已知半径球/圆柱、极点和窄带尺度；先局部复用，避免每次查询遍历全部 CAD 边。

### 4.3 增加前沿式候选与布局优化

- 在 `SurfaceRefinementCandidates` 中对约束或当前前沿边，按局部三维目标尺寸构造近等边的 off-centre 候选，与现有外心/内部候选比较。
- 在局部切平面中构造并映回合法 UV 图表；周期分支、有效裁剪域和局部曲面度量必须核验，不能直接对越界 UV 做钳位来获得“有效点”。
- 候选通过现有事务插点；检查整个实际空腔的新片方向、约束、物理尺寸/偏差/法向，失败回滚并记录原因。
- 优先采用改善形状且满足局部尺寸的候选。已有必要短边只限制局部可行性，不能把所有相邻差片都标为不可改善。
- 在现有完整一环翻边/移动框架内优化；边界节点固定或经共享边协调移动。新增形状统计用于判定改进，原几何/质量验收仍保留。
- 插点顺序/停止目标变化属于明确的新算法版本；与旧输出比较质量和几何，不要求跨算法版本字节一致。

### 4.4 质量阶段通过条件

硬门槛：凹球保持 √2 超标 0、约束/共享棱正确、无无效片/同部件自交，同一偏差和法向采样要求通过，工作及节点预算不突破。phone 保留独立部件和关系记录，差片数量及最差质量不恶化。

布局目标：在片数 ±10% 且几何要求相同的条件下，凹球 P5 最小角和 P5 形状指标不低于旧自研结果，至少一项明显提升；初始目标为 P5 最小角提升 3°或 P5 形状指标提升 10%。同时列出与 Gmsh 的差距，不能只报最差片。

达到上述目标称“布局改善”；仅当选定对照中两项与 Gmsh 相差均不超过 10%，且局部尺寸跳变没有恶化时，才称“本次凹球对照接近 Gmsh”。这些是本阶段工程验收目标，不是所有 CAD 的质量保证。

## 5. oneTBB 并行设计

### 5.1 接入与共用 API

- 拟新增纯 C++ `mesher/MeshingExecutionOptions.h`：`maxConcurrency=1` 为明确串行；`0` 为自动选择，正整数为上限。有效值及实际调度线程数写入运行记录。
- 表面和未来体网格可复用该配置；几何判据仍各自属于 SurfaceCriteria/未来 VolumeCriteria。配置通过入口传递，不隐藏在全局变量或 Qt 对象中。
- CMake 增加 `MESHSTUDIO_ENABLE_TBB`，启用时用 `find_package(TBB CONFIG REQUIRED)` 和 `TBB::tbb`；单独串行构建继续可用。依赖缺失或请求并行而构建不支持时明确报错。
- 固定经当前 MSVC/Windows 构建验证的 oneTBB 版本，记录来源、许可证及 DLL 部署；本机现有 OCC `USE_TBB=OFF`，无需为本阶段重编 OCC。
- QtConcurrent 继续启动后台任务，内部 oneTBB 使用任务专属 `task_arena` 控制并发。首版不嵌套各层并行，也不自动占满所有逻辑核心。

### 5.2 先保证串行的数据拆分等价

把每面工作提取为 `FaceMeshingTask.h/.cpp`，保持内部算法顺序。任务输入为冻结边界、解析参数和几何查询上下文；任务输出为局部点/三角形、逐面 UV、分裂请求、统计及诊断。

先以单线程执行新任务路径，与拆分前版本比较规范化坐标/连接、面/棱/部件/UV标签、工作统计和诊断。通过后再调度多线程，避免把拆分带来的质量变化归因于并行。

### 5.3 并行阶段与串行协调

```text
准备 CAD 与拓扑 → 共享棱采样并冻结当前轮边界
    → 并行计算各活动面的局部结果
    → 按 CAD 面 ID 合并点、请求、统计及诊断
    → 串行去重并应用共享边分裂，更新相邻面版本
    → 重新计算受影响面，直到收敛或明确失败
    → 全量验收、部件关系核对 → 输出
```

共享边登记、全局编号、节点回收、预算裁决及最终部件关系查询首版串行。不同面任务不能写同一个全局 points/vector；共同边界只读，内部点采用局部编号，按固定顺序映射至全局编号。

预算不能简单地用原子计数让先运行的面抢占。面任务记录事件及工作量，协调阶段按固定顺序扣减；若剩余预算不足，丢弃未提交的推测结果，并以剩余预算串行重放当前面以给出同语义失败。不得把 200000 自动变成“每个面 200000”。推测执行另设批次/并发内存限制，记录丢弃的计算量和内存开销，不把它们隐去。

### 5.4 线程安全与失败处理

- OCC 为每个工作上下文准备独立曲面/曲线求值器和缓存；核验 B-spline 等底层 Handle 是否共享可变状态。仅复制 adaptor 不视为已经线程安全；必要时复制对应几何对象，未验证类型走明确记录的串行求值路径。
- 自定义 GeometrySource/MeshSizeField 默认不具有线程安全保证；增加显式并发查询能力/工作上下文契约。未支持的实现默认串行，并报告有效并发。
- MeshingObserver 每任务独立统计，带时间/任务身份再合并；不能把并行嵌套阶段写入现有单个阶段栈。累计 CPU 时间与墙钟时间分开。
- 取消使用共享原子标志，现有 progress 回调由协调线程调用；工作任务检查标志，不直接调用 UI 或用户回调。同步周期有界，测试处理中取消的响应。
- 工作线程异常转为携带 CAD 面/阶段的失败结果，取消其他任务并等待退出；不返回部分网格为成功。任务寿命内持有完整上下文，禁止后台线程引用已销毁的临时几何。

### 5.5 并行通过条件

- 新任务路径 1/2/4 线程重复运行，规范化网格及 CAD 标签/UV/关系集合相同；固定提交顺序下预算和失败位置稳定。取消场景允许完成工作量不同，但不得成功输出部分结果。
- 共享棱、孔、周期缝、极点、工作/节点预算临界值、取消、异常，以及样条查询压力回归通过；工具可用时做数据竞争检测，并记录检测平台。重复运行无差异不能单独证明没有竞争。
- 凹球质量阶段结果和 phone 部件关系保持；全量独立 CAD 审计通过。
- 单线程/2线程/4线程各三轮串行计时，报告中位数、内存及各阶段占比。phone 4线程总体耗时降低 25% 作为首轮性能目标；未达到则报告受串行阶段限制，不宣称已完成提速目标。
- 凹球只有少量 CAD 面，允许收益有限；小模型自动选择串行阈值由实测确定，不预先承诺固定倍数。
