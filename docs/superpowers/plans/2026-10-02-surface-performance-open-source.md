# CAD 表面网格性能：开源实现对照

状态：源码对照和分阶段方案已整理；本轮未修改生产算法，尚未做函数级计时或 Gmsh 同模型性能测量。

## 实测基线与比较边界

- `move.stp` 当前 Release 核心生成及内部校验一次实测 96.7896 秒，导入和适配后总计 99.3567 秒；2283 面，98584 三角形、48690 节点。详见同目录 `2026-10-02-move-surface-benchmark.md`。
- 首张面完成约 56.94 秒，包含所有共享棱准备和第一面的构造/细化，不能据此断言全部是棱采样耗时。原进度在第 324 面附近停留，需要单面计时定位。
- 未测 Gmsh 同模型时间，不能给出速度倍数。Gmsh 的尺寸/曲率参数与本项目的三维边长、采样偏差、法向角、相交拒绝要求需要分别对齐。

## Gmsh 的具体做法

- `meshGFaceDelaunayInsertion.cpp:1033` 的 `bowyerWatson` 从 `AllTris.begin()` 取当前最坏三角形；`1290` 的 Frontal-Delaunay 使用 `ActiveTris`。排序依据是缓存的归一化外接圆半径（头文件 `compareTri3Ptr`），不是每次遍历所有三角形计算评分。
- `recurFindCavityAniso` 沿邻接扩展空腔；`insertVertexB:685` 构造空腔边界扇形和外侧邻片，检查局部面积守恒/距离/可见性。失败恢复原空腔删除标记并释放候选单元，成功只连接这一局部；不是整张面网格副本事务。
- `bidimMeshData` 保存逐点 UV 和尺寸；`OCCFace.h:23` 保存曲面对象、适配器和参数范围。`OCCFace.cpp:246` 的法向/D1/D2使用保存的曲面；`437` 的曲率使用 `BRepLProp_SLProps`。它仍会访问 CAD，并非所有几何都预计算。
- `meshGEdge.cpp:407` 自适应积分 `|C'(t)|/h(C(t))`，保留 `IntPoint` 的参数、尺寸、累计积分；`983` 附近沿表反求节点位置，并作尺寸渐变处理。这是边界初值布点的参考，不能直接替代本项目对折线偏差/相邻面法向的最终检查。
- `Generator.cpp:398/542` 获取线程数，`431/590` 以 OpenMP `schedule(dynamic)` 分发曲线/面。边界层、某些四边形算法、周期主从网格和挤出等情况会退回一个线程；普通曲面的周期缝与这里的周期主从网格不是同一概念。官方手册也明确 1D/2D 是按几何实体并行。

这些是提高效率的结构机制，尚不能证明在用户那次 Gmsh 运行中各自贡献多少时间。

## Netgen 和 CGAL 的参考点

- [Netgen meshing2.cpp](https://github.com/ngsolve/netgen/blob/v6.2.2603/libsrc/meshing/meshing2.cpp)：`300` 创建已有面片包围盒树，`471` 选前沿基边，`488` 取局部邻域，`1086` 只查询候选包围盒内的已有面片，成功后更新树及前沿。
- [Netgen adfront2.cpp](https://github.com/ngsolve/netgen/blob/v6.2.2603/libsrc/meshing/adfront2.cpp)：`277` 的 `GetLocals` 使用边/特殊点空间树。`219` 的 `SelectBaseLine` 是游标查找并带整表回退，不应描述为所有搜索都是堆或恒定时间。
- [Netgen OCC 适配](https://github.com/ngsolve/netgen/blob/v6.2.2603/libsrc/occ/occmeshsurf.cpp)：保存局部切平面/UV 映射；依据 D1 建立局部变换，`ToPlane`/`FromPlane` 处理局部点。参考其图表接口与局部搜索；没有理由为了速度把已确定的 CDT 主路线改成完整规则前沿法。
- [CGAL Refine_faces](https://github.com/CGAL/cgal/blob/v6.1.1/Mesh_2/include/CGAL/Mesh_2/Refine_faces.h)：`Bad_faces` 是质量排序的双向映射；`before_insertion_impl` 移除空腔中被删除的记录，`after_insertion_impl` 更新域标签，`compute_new_bad_faces:316` 只检查新点一环。
- [CGAL Refine_edges](https://github.com/CGAL/cgal/blob/v6.1.1/Mesh_2/include/CGAL/Mesh_2/Refine_edges.h)：候选点侵入约束边时加入边处理层并让面候选稍后重试；分边后检查局部星形边界。二维域标记的局部继承必须以不穿越约束的空腔为前提，不能无条件照搬到跨 CAD 面重建。
- CGAL Mesh_2 是二维细化参考，不是现成的 CAD 表面生成器。本轮没有调用或移植其算法库。

## 当前实现的已确认额外工作

| 路径 | 已确认行为 | 代价/限制 |
| --- | --- | --- |
| `Delaunay2D.cpp:200` | 每次插点复制完整 `Mesh2D`，完成后全面 `validate` | 随单面规模增长的额外线性工作；初始构造每个边界点也走此路径，外层又检查一次 |
| `Delaunay2D.cpp:76/134` | 查重扫描所有点；每次分配整三角数量的空腔标记 | 即使空腔很小仍与整面大小有关；邻接空腔 BFS 已有，应保留 |
| `CadSurfaceMesher.cpp:174` | 分内部边遍历全部三角形找两邻片，再查所有点、复制网格和全面检查 | 已有 `findHalfedge` 可查两侧，但这一分边路径尚未使用 |
| `CadSurfaceMesher.cpp:972` | 每轮细化重新调用 `classifyConstrainedDomain` | 分类先全面校验，再建立约束表、遍历凸包、全域 BFS；边界不变的局部插点也重复做 |
| `CadSurfaceMesher.cpp:982` | 游标扫描判据，查三点 ID 的度量缓存 | 缓存避免部分 CAD 重算，但仍遍历未变化单元；未按坏单元队列增量推进 |
| `Constrained2D.cpp:recoverEdge` | 初始恢复先扫描相交边；每次取边又扫描三角形查邻片 | 复杂裁剪面可能放大；不是每张面或每次插点都一定触发全部恢复 |
| `SurfaceChart.cpp:51` | 普通尺寸样本查一次范围、一次 D1、五次法向 | 边采样另查端点/中点法向，同一中点重复；递归子段重新查询继承端点 UV/法向 |
| `OccCadGeometry.cpp:129–171` | 点/D1/法向/范围查询重复创建 OCC 适配器，edgeUV重复查 p-curve | 面内已有点/法向缓存，但共享棱采样和尺寸差分仍绕过该缓存 |

一次普通非奇异的共享棱区间/面使用中，尺寸估计需要五次法向，区间角度检查再查三次法向，至少一个完全相同的中点 D1 重复；差分四点位置不同，不能说八次都能合并。适配器构造与 CAD D1 各自耗时尚未测量。

最终相交检查已有 BVH，不是暴力遍历所有三角形对。面构建缓存、共享边登记、局部翻边和三角形/点法向缓存已经存在；方案是在这些基础上补外围增量维护。

## 建议的实现顺序与边界

### 1. 先给耗时分账

- 在测试工具接入可选统计观察器，拆分共享棱采样、每面初始化、约束恢复、细化（分类/测量/拓扑修改/翻边）、压缩与最终验收；记录 CAD 查询次数、空腔大小、完整副本数量/规模、整表访问量和前十个最慢 CAD 面。独立双向审计单列。
- 范围：`tests/CadGeometryAuditTest.cpp` 与必要的可选核心统计钩子；没有监听器时不在每次 CAD 查询前后读高精度时钟。计数、互斥耗时与包含子调用的耗时分别报告，避免重复相加。
- 先定位 `move.stp` 首面前区间和源 face 324；独立单面粗边界不能替代全模型共享边条件。优化前后保持原参数/预算至少三次，报告中位数和范围。本项尚未实现或重测。

### 2. 降低几何查询重复

- 范围：`OccCadGeometry.{h,cpp}`、`SurfaceChart.{h,cpp}`、共享棱局部评估结构。
- 保存曲面/曲线适配信息、参数范围、按 `(face,edge,branch)` 区分的 p-curve；保留 OCC Location 变换、裁剪、周期分支和方向，不能换裸曲面后丢失变换。
- 递归携带端点 UV/点/法向，只计算新增中点；面内合并同 UV 点/D1/法向，保留有限值、奇异检查和诊断。
- 可选几何微分能力返回曲率/二阶导数，OCC 用解析能力，纯 C++ 测试几何保持差分回退。球/柱/剪切参数化对照；估计尺寸仅用于布点，输出几何判据继续验收。
- 缓存只在不可变模型的一次生成期有效，不量化 UV 合并不同样本。共享 OCC 适配器未证明线程安全前不能多线程共用可变求值器。

### 3. 局部拓扑事务

- 范围：`Mesh2D.{h,cpp}`、`Delaunay2D.cpp`、`Constrained2D.cpp`、`CadSurfaceMesher.cpp` 分边调用。
- 复用半边表查邻片；局部修改记录替代整网格副本，覆盖空腔、外侧邻接、半边及 swap-erase 搬移尾部单元。失败恢复原状态；成功检查受影响单元，面完成后全面验收。查重索引与访问代号避免整表扫描/清零。
- 以旧副本模式作测试对照，验证失败后完全不变、约束保留、退化拒绝和紧凑删除搬移。不能直接去掉副本和验证而损失原子性。若需要大范围容器重构，先提交具体设计供用户确认。

### 4. 域标签与两层待处理队列

- 范围：`CadSurfaceMesher.cpp` 与二维域维护接口。
- 初始域分类一次；不跨约束的局部空腔/分边/翻边继承所属域，只在共享棱/裁剪边界改变后重分类相关面。
- 约束边优先队列与坏三角形队列，仅更新变化单元和一环；缓存带几何/尺寸场/边界版本。triId 会 swap-erase，队列必须有版本并处理搬移/删除，不能保留裸编号。
- 保留稳定同分决胜、取消及共同预算。后续单独试度量外心/off-center/前沿启发式，比对插点/翻边数；不把候选策略改变混入第一批纯性能改动。

### 5. 再做面级并行

- 共享棱完成后，面任务读取边界快照、写本地节点/片，由协调器合并全局节点 ID/诊断。分边请求集中提交，关联面按版本失效；相交反馈、公共预算和取消统一协调。
- CAD 求值器线程隔离和结果可复核后才实施。2283 张面有并行机会，但单个热点面、共享棱和全局验证仍限制加速，不能把八核等同八倍加速。

## 自研路线和可复用 API

- 保留参数域 CDT + 三维判据驱动细化；学习局部数据结构/求值/调度，不依赖第三方生成结果。
- `GeometrySource`、三维 `MeshSizeField`、进度/取消、诊断/统计继续共用；微分扩展为可选能力，OCC 类型不能进入纯 C++ 核心。
- 共享 CAD 节点及输出 `SurfaceMesh3D`、面/棱标签、逐面 UV 保留，供未来四面体边界入口复用。
- 表面半边与二维域队列不直接充当四面体数据结构；未来复用事务/版本/调度原则和共同接口。当前四面体算法不改。

## 验收门槛

- 缓存/查找优化对照坐标、连接、标签和诊断；候选顺序改变若生成不同网格，单独说明并重新验收。
- 事务/标签覆盖双孔、凹域、窄条、共享棱、周期缝、极点和翻折回滚；局部域标签对照原全面分类。
- 保留失败/取消/预算语义及最终约束、闭合、方向、退化、相交检查。ball 独立双向审计、保存往返回归；补 move 独立审计再作为真实模型质量依据。
- 性能分列导入、生成、验收和面片数，不能通过放松 δ/θ、增预算、删相交检查或丢小特征获得速度。
- Gmsh 基准分单/多线程，记录算法、尺寸/曲率参数和测得质量。每 2π 元素数不等于本项目法向变化或几何偏差；还需对齐导入拓扑、单位和退化处理，不能仅比较 h 或三角形数。
