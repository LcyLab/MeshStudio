# 自研 CAD 表面三角网格：性能改造详细实施计划

> 状态：用户批准的 A—F 已实现并完成工程验收。GUI 使用实际窗口自动操作与图像检查，用户手动点击验收未进行；G/H 后置。各阶段实测报告记录实际接口、命令及结果，本文保留原设计说明。
> 执行方式：用户确认后使用 `superpowers:executing-plans` 在当前工作区逐任务推进。无需创建分支/worktree，不自动提交，不默认派发子代理。

**目标：** 保持参数域 CDT 加细化的自研路线，在原几何要求下减少重复 CAD 求值和整网格操作，并用真实模型验证效率、质量及未来体网格 API 的兼容性。

**架构：** OCC 负责几何求值；纯 C++ 核心负责共享棱、二维拓扑和三维判据；Qt/VTK 负责显示和保存。先优化串行算法，再决定是否启用面级并行。

**技术栈：** 现有 C++/CMake/VS2022、OCC、Qt5、VTK；本阶段不引入第三方三角化算法库或新增构建依赖。

## 1. 审阅重点

建议先看这五项：

1. **顺序：** A 计量 → B 求值复用 → C 局部事务 → D 域标签 → E 待处理队列 → F 完整验收。
2. **首批改造：** A—D 保持现有候选点选择和几何要求；E 的处理顺序可能改变网格，但仍使用原判据。
3. **延后项目：** 解析曲率/新候选点策略为 G，面并行为 H；在串行阶段有测量依据后再决定实施。
4. **正确性：** 失败回滚、共享节点、周期缝/极点、有限值检查、最终相交检查均保留。
5. **四面体复用：** 共用几何、尺寸场、进度/取消、诊断/统计及表面边界标签；不改当前四面体算法，不强行共用二维半边数据结构。

原计划编写时未改算法；当前实现与验收见同目录阶段 A—F 报告。通过所测模型不代表任何 CAD/参数组合都能成功。

## 3. 参数和成功语义

- h、h_min、δ 使用导入后的坐标单位；θ 为角度。保留现有 5% 边长判断余量，面板参数意义不变。
- h_min 是常规尺寸下限，小特征/几何条件允许突破并诊断；ρ 是受尖角/边界限制的质量软目标。统计中必须列出冲突位置，不能靠忽略它们提速。
- δ 继续是采样偏差要求；独立审计另报最近距离，不混为同一个测量定义。
- 不提高 maxIterations/maxVertices 来掩盖算法停滞；测量超时只用于控制实验观察，超时结果必须记失败/取消。
- `ok=true` 仍需通过最终约束、关联/闭合、方向、退化/翻折、几何采样和 BVH 相交检查。
- 每阶段记录节点/面片数、插点/翻边/边分裂数、质量统计、诊断和耗时。不同网格规模不能只比较秒数。

### A1. 加可关闭的统计观察接口

```cpp
enum class MeshStage {
    BoundarySampling, InitialTriangulation, ConstraintRecovery,
    DomainClassification, Refinement, GeometryEvaluation,
    TopologyUpdate, Legalization, MeshAssembly, Validation
};
enum class MeshCounter {
    GeometryQueries, WholeMeshCopies, CopiedPoints, CopiedTriangles,
    TriangleVisits, PointVisits, CavityTriangles, WholeDomainClassifications
};
struct MeshEntityRef { int dimension = -1; int id = -1; };

public:

    virtual void stageEnd(MeshStage, MeshEntityRef) = 0;
```

## 8. 阶段 C：局部拓扑事务和索引

拟定编辑报告：

## 10. 阶段 E：版本化待处理队列

**修改范围：** `SurfaceRefinementQueue.{h,cpp}`、`CadBoundaryRegistry.{h,cpp}`、面细化协调。

这里开始可能改变候选处理顺序和最终网格；必须与 A—D 分开提交验收记录。

拟定面候选条目：

```cpp
struct SurfaceTriangleTicket {
    int face = -1;
    int slot = -1;
    std::uint64_t topologyVersion = 0;
    std::uint64_t criteriaVersion = 0;
    int priorityClass = 0;
    double violation = 0;
    std::array<int, 3> vertexKey{};
};
```

队列优先级：翻折/硬几何条件优先，质量软目标其次；类内按超限比递减，再按稳定 face/顶点键决胜。非有限评分拒绝；排序不依赖指针地址。

- [x] 先测槽位复用、尾片搬移、同分评分、相交反馈更新 criteriaVersion、共享分边旧请求失效；旧条目不得作用于新三角形。
- [x] 首次仅评估域内有效片，插入坏片；每次编辑只使删除/变化/搬移条目失效，重测新片和需要重测的一环。
- [x] 被搬移但几何未变的片复用判据，更新 slot/version 并重新入队；不能因只更新“空腔新片”漏掉搬来的坏片。
- [x] 约束边工作队列存 CAD 棱、区间、源面、边界版本；集中优先处理有效分边请求，相同参数去重、公共节点只建一次。
- [x] 面候选侵入受保护约束时先处理边问题再重试；沿用现有允许分边判据，不把质量软目标变成无限切尖角的硬条件。
- [x] 队列为空后做一次全面判据验收；发现遗漏列为失败/维护错误，不能每次依赖全面扫面作为正常补漏。
- [x] 懒删除积累过多时仅对该面的活动条目压缩，记录次数和峰值；避免历史票据无限增长。

**完成标准：** 判据遍历随新/变化单元推进；最终全面验收未发现漏处理；重复运行确定性可复核；几何和公共工作预算语义不变。新网格不要求连接与旧游标顺序相同，但全部质量、共享标签、保存往返要求重新验收。

### 11.3 性能验收规则

- 每阶段比较同参数三轮普通计时中位数和范围，观察器开启记录只分析原因；不得把不同负载、不同节点量或观察成本混为加速。

- 如果改善落在运行波动内，不宣称提速；必要时只为该不确定性补两轮，不能无界重复测试。
- 若变更导致可靠性/内存/质量下降，保留日志，撤销本阶段相关改动方案并修根因；禁止覆盖用户其他改动或用全仓 reset 回退。

## 13. 阶段 H：面级并行的独立设计边界

不能只给现有 face 循环加并行 pragma。它当前写共享节点池、边界失效、预算和诊断，直接并行会产生竞争。

拟定协议：

1. 协调器完成共享棱，建立带版本的只读快照；边界节点 globalId 已固定。
2. 面任务使用自己的 OCC 求值器/缓存、本地内部节点/片/UV、诊断和耗时；不直接追加公共节点池。
3. 分边请求返回 `(edgeId, interval, parameter, boundaryVersion)`；协调器验证版本、去重提交，并使全部关联面失效。
4. 按稳定 face 顺序合并内部节点并重映射标签；只有共享棱已有的 ID 直接复用，不能用坐标焊接补一致性。
5. 全局预算由协调器预留工作/节点配额，任务在配额边界暂停提交续配请求；所有废弃面工作也计入。超预算明确失败，不能每线程各自获得整份预算。
6. 取消信号线程安全，任务协作退出；失败/异常聚合后不发布成功网格。最终闭合/几何/相交检查统一进行。

验证：1/2/4 工作线程；共享边分裂、相交反馈、取消、极低预算；每次重复结果可复核，不残留旧边界版本。峰值内存与并行任务数也必须报告。

**开启条件：** A—F 完成、CAD 求值器线程隔离可证、单线程结果可重现；提交具体并行设计供用户审阅后执行。未来可复用任务/配额协议，二维面算法本身仍独立。
